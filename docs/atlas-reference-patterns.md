# Atlas Reference Patterns

Internal note for Atlas information architecture and review.

## Reference Inspirations

Atlas takes inspiration from taxonomy and landscape work such as Robert Lawrence Kuhn's "Landscape of Consciousness" model and independent interactive consciousness-map projects that present an overview map, category navigation, clickable entries, structured detail panels, and references.

Do not copy external Atlas code, assets, styling, wording, visual treatment, or trade dress. These references are useful only as interaction-pattern and information-architecture signals.

## Reusable Principles

- Atlas should show the shape of a field, not just list facts.
- Start with an overview so the reader can see the major families, movements, systems, or lineages before drilling down.
- Make the category/group structure visible as a first-class object.
- Let readers click into nodes or entries for structured details instead of forcing all explanation into the overview.
- Every entry should explain why the thing matters, not merely define it.
- Sources and provenance should be accessible from review/admin surfaces and eventually available in a reader-appropriate public form.
- Maps should support comparison, contrast, influence, and neighboring positions; they should not force a false ranking unless the map recipe explicitly calls for ordered development.
- Atlas should collect, organize, and clarify before it judges.
- This pattern must generalize beyond consciousness into economics, music, science, art, politics, mathematics, systems, literature, and other domains.

## Production Implications

- Generation should optimize for useful structure: groups must be distinct, navigable, and reviewable.
- Source selection should cover multiple conceptual lanes before generation, so a map does not collapse around one source or one vocabulary.
- Category review is part of production, not a cleanup afterthought.
- Provenance is part of the content contract: claims, contributors, texts, and relations need traceable support.
- Public design can evolve later, but the content model should already support overview-first exploration, structured node details, comparison, and source-backed review.
